# 课程完成与报告契约

## 完成规则

- 步骤 1–15：答对本步全部固定单选题即完成。
- 步骤 16：服务端成功生成当前学生、assignment、attempt 与 manifest 下的实验报告即完成。
- 访问页面、停留时长、切换筛选、查看图表和运行回归都不直接改变完成度。
- 学生无需另行提交实验操作，也不必为了拿到完成对勾执行指定点击流程。

## 理解检查

- 当前题库版本为 `course-quiz-v2`，覆盖步骤 1–15，共 21 题。
- 题干和选项公开给前端，正确答案只在服务器保存。
- 每次提交立即返回逐题正误与解释，允许不限次数重试。
- 答错不会持久化；一整步全部答对后才记录事件并签发不可见的 `quiz_id`。
- `quiz_id` 绑定账号、assignment、attempt、manifest、步骤、题库版本和完整答案。
- 修改答案、切换题库版本或进入新 attempt 后，旧 `quiz_id` 不再有效。
- 报告记录每道题的题干和学生最终通过的选项，不记录错误尝试。

## 自动保存的实验过程

系统按步骤自动保存有意义的最终状态，例如：

- ICIO 切片和选中的单元格；
- 年份、指标、对比对象、图表视角和下钻对象；
- 查看过的政策事件类别与事件；
- 学生最近一次实际运行的回归设计及服务器签发的 `run_id`。

这些状态中的当前选择用于刷新恢复，累计的观察与运行记录用于报告摘要；系统不追踪逐次点击，
这些状态也不是完成条件。实验状态缺失或格式无效时，
报告忽略该项并继续生成，不会把它变成新的隐性门槛。

## 报告

- 第 16 步生成前，服务器只检查步骤 1–15 的答题是否全部通过。
- 报告包含最终答题、当前产物 QC、自动保存的关键实验快照和数据 provenance。
- 只有与当前账号、assignment、attempt 和 manifest 匹配的真实 `run_id` 才会被服务端复估并写入报告。
- 学生没有运行某一步回归时，报告写明“未记录学生运行”，不生成系数，也不运行默认模型。
- 教师可依据报告的一致性、研究设计、解释和边界意识评分；完成对勾本身不是教师评分。

## 题库升级

修改题目、选项、答案或完成契约时必须提升 `QUIZ_VERSION`。本版本不兼容旧 session；发布前先
备份教学数据库，通过全部预检与健康检查后，再执行：

```bash
uv run gvcsim classroom-reset-attempts --quiz-version course-quiz-v2 --confirm
```

该命令会撤销仍可写的旧 attempt 收据、归档旧 attempt 并创建空白 attempt；历史 session、报告、
提交和评分保留。命令按题库版本写入审计标记，同一版本重复执行不会再次重置。
