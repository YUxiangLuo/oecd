# 课程学习证据契约

系统把“完成一步”定义为两类证据同时成立：

1. 学生确实完成了本步要求的真实操作，且服务器能够用当前数据或运行记录复核；
2. 学生答对了本步 1–3 道固定单选题。

访问页面、切换标签、只做操作或只答题都不算完成。步骤 1–15 使用这套规则；步骤 16
以服务器生成的报告作为完成证据。

## 理解检查

- 当前题库版本为 `course-quiz-v1`，覆盖步骤 1–15，共 21 题。
- 题干和选项公开给前端，正确答案只在服务器保存。
- 每次提交立即返回逐题正误与解释，允许不限次数重试。
- 答错不会写入学习证据事件；一整步全部答对后才写入事件并签发 `quiz_id`。
- `quiz_id` 绑定账号、assignment、attempt、manifest、步骤、题库版本和完整答案。
- 修改答案、切换题库版本或进入新 attempt 后，旧 `quiz_id` 不再有效。
- 报告记录每道题的题干和学生最终通过的选项，不记录错误尝试。

## 真实操作门槛

| 步骤 | 服务器核验的操作 |
|---:|---|
| 1 | 主动选择 ICIO 切片和一个具体数值单元格；服务器重读原始表核对行、列与数值 |
| 2 | 选择停止、修正或披露后继续；修正必须复检通过，披露必须覆盖全部当前异常，停止会锁住下游报告 |
| 3–6 | 对比至少两个经济体的指定国家×行业指标；服务器按当前年度产物重算观察值 |
| 7–10 | 保存指定图表、指标和至少两个对比对象；服务器重算图中使用的观察值 |
| 11 | 关税、制裁、出口管制各查看并保存一个登记事件，同时确认冲击数据 QC |
| 12 | 保存贸易主回归、无控制基准和有控制模型；两次设计只能改变控制口径 |
| 13 | 保存无交互与有交互的生产回归；两次设计只能改变交互设定 |
| 14 | 保存长度指标的事件研究运行 |
| 15 | 保存网络主回归及完全相同设计的安慰剂运行 |
| 16 | `report_key` 必须指向当前学生、attempt 和 manifest 下由服务器生成的报告 |

步骤 1–11 的操作先写入 append-only `learning_evidence_events`，再签发 `evidence_id`。
步骤 12–15 使用服务器实际估计后签发的 `run_id` / `placebo_run_id`。所有凭证都绑定
当前 assignment、attempt 与 manifest；改变已签名的操作内容会让凭证失效。

## 完成度、报告与评分

- 完成对勾只表示“操作可复核且本步选择题全部答对”，不是教师评分。
- 第 16 步生成报告前，服务器重新检查步骤 1–15 的全部凭证，并重新估计四个回归步骤。
- 报告包含操作摘要、最终选择题答案、QC 处置、回归设计、结果与数据 provenance。
- 教师仍可依据报告的一致性、可复现性、研究设计和边界意识给出总分与反馈；系统不再要求
  学生逐步填写自由文本模板。

## 题库升级

修改题目、选项或正确答案时必须提升 `QUIZ_VERSION`。上线新题库前先备份教学数据库，再执行：

```bash
uv run gvcsim classroom-reset-attempts --quiz-version <新版本> --confirm
```

该命令会撤销仍可写的当前 attempt 凭证、归档旧 attempt 并创建空白 attempt；历史 session、
报告、提交和评分保留。命令按题库版本写入审计标记，同一版本重复执行不会再次重置。
