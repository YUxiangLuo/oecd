> 历史设计方案：保留当时的决策和实施记录，不作为当前接口或验收承诺。当前行为见[技术手册](../技术手册.md)，学生操作见[实验手册](../实验手册.md)。

| 项目 | 内容 |
| --- | --- |
| 日期 | 2026-10-06 |
| 基线 | v1.0.0 |
| 性质 | 交付后改进的分析与路线建议，不含实现 |
| 问题 | 四个可视化步骤看起来是"为两国对比专门做的"；希望图表更丰富、UI/UX 更好 |
| 硬需求（雇主） | ① 必须有国家对比；② 必须有按时间序列显示的图表。两者在每个可视化步骤都要能被明确演示 |

硬需求决定了重构的边界：国家对比和时间序列图不能削弱，也不能藏到次级入口；要改的是"对比是唯一入口、两国是唯一形态、历年是唯一主图"这三件事。

## 1. 现状：两国对比被写进了哪一层

"两国"不是一个界面习惯，而是从数据契约到报告的一条硬约束。要松绑必须知道它在每一层的形态。

### 1.1 数据契约（学生会话）

- 步骤 6–9 的步骤状态 `VizStepState` 用 `compared: string[]` 加 `observations: VizObservation[]` 表示报告材料，并以 `indicator_selection`（`first`、`second`、`industry`、`metric`、`start/end/year`、`view`、`limit`）记录"学生最后看的那张图"。`second` 为空字符串表示没有对比国家。
- 前端判定材料完整的函数 `materialComplete()`（`indicator-model.ts`）第一条就是 `countries.length !== 2 → false`，并要求两国的 `(industry, metric, year)` 身份集合完全一致，也就是严格配对。
- 步骤 9 另有一套：`network-trend.tsx` 的 `canRecord` 要求 `selected.length === 2`，并且趋势视角需要两国至少两个共同年份、排名视角需要至少一个行业两国都有值。

### 1.2 后端门槛与报告

- `report_gate.py` 的 `_indicator_material_complete()`（步骤 6–8）和 `_network_material_complete()`（步骤 9）都以 `len(compared) == 2` 开头，再要求观测国家集合等于 `compared`、同 scope、同 release、同 source、两国键集合一致。门槛不满足时步骤 15 显示"报告材料未齐全"，不能生成报告。
- `report_observed.py` 的 `_observed_chart()` 按 `compared` 的顺序为每个国家画一条 series，再叠加全部经济体的中位数与四分位带作参照；`_rank_reading()` 按 `countries` 逐国写"第 N 位"。报告正文固定写"比较对象：A、B"或"系统自动记录的比较"。
- 自动记录规则（技术手册 8 节）：步骤 6–9 记录最后查看的一张完整图表，未选对比国家时"图表照常显示但不覆盖已有材料"。界面因此必须时刻提醒"报告材料需要一个对比国家"。

### 1.3 探索器（步骤 6–8 共用）

`IndicatorExplorer` 是一个 750 行的组件，三个主题（`trade.tsx`、`production.tsx`、`length.tsx`）只提供指标表、构成分项和定位图坐标轴，界面完全相同：

| 视角 | 主图 | 与"两国"的关系 |
| --- | --- | --- |
| 历年变化 | `IndicatorTrendChart`：A、B 两条线 + 全球中位数虚线 + 中间 50% 灰带 | 线的数量由 `selected` 决定，技术上支持 1 条或 N 条，但材料只认 2 |
| 全球分布 | `DistributionStrip`：当年全部经济体分布条带，高亮 A、B；选了行业时退化为两国配对柱 | 分布本身与两国无关，是被"高亮两国"包装成对比 |
| 构成分析 | `CompositionBar`：单年两国并排，或历年两国分面 | 分面逻辑硬编码为"每国一面" |
| 前后向与位置（仅步骤 8） | 两张趋势图 + `LengthPositionTrajectory` | 同上 |
| 定位行业 | `IndicatorPairBars`：按 A 排序、B 对齐的配对柱 | 组件名字就是"配对" |

另有两张图被放进弹窗（`chart-modal.tsx`）：`QuadrantScatter` 定位图（全部经济体散点，高亮所选）和 `RankBarChart` 前 20 排名。这两张恰恰是"不需要两国"的图，却是补充地位。

### 1.4 步骤 9 的独立实现

`network.tsx` + `network-trend.tsx` + `network-ranking.tsx` 约 470 行，重复了探索器的 A/B 选择、口径句、自动记录、锁定逻辑和读数表，但控件顺序、视角切换组件（按钮组而非 `LensNav`）、排名图组件（`NetworkRanking` 而非 `IndicatorPairBars`）都不同。贸易网络图（`NetworkViz`）和行业热力表（`HeatTableViz`）同样在弹窗里。

## 2. 诊断：为什么"看起来像专门为两国对比做的"

1. **材料门槛反向塑造了界面。** 因为报告只接受两国配对读数，界面把"选对比国家"做成了前置条件，单国浏览被标成"不会记录"。学生感知到的是"必须先选 B"，而不是"先看懂一个国家"。
2. **四个视角是同一张两国图的四种切法。** 历年、分布、构成、行业都以 A/B 为主语。缺少三类常见读法：一国全貌（一国的多指标仪表）、多国并列（3–5 国小倍数或点图）、全体（分布与排名作为主图而不是弹窗）。
3. **三个步骤界面完全一样。** 步骤 6、7、8 只换指标表，学生连续三步面对同一套控件，没有"这一步的看点"。主题化的东西（出口价值来源的构成、生产四类路径、前后向位置轨迹）要么藏在视角里，要么只在步骤 8 出现。
4. **控件密度高、语义靠口径句兜底。** 一行 4–5 个下拉（国家 A、对比国家 B、比较范围、指标）加第二行年份，切换视角时控件增减；"当前比较口径"那行粗体承担了解释组合的责任。
5. **步骤 9 与 6–8 不一致。** 视角切换、控件顺序、排名图形态、材料卡文案各有一套，学生到第 9 步要重新适应。
6. **"更丰富的图"已经存在但被降级。** 定位图、排名、贸易网络、热力表都在弹窗；弹窗关闭后回到两国主图，学生很少在那里停留。

## 3. 可以松动的东西与必须守住的东西

**必须守住**：报告材料仍要"可复现、读数完整、同 release、同口径"（指纹、门槛、报告渲染都依赖）；每步一份当前材料、提交后锁定、"学生选定 vs 自动记录"的区分；桌面 ≥1200 px 的单一断点；现有会话（两国材料）在新规则下仍然完整。

**雇主硬需求下必须保留并可演示**：每一步都有"国家对比"视角（至少两国同图、同口径、同刻度）和"时间序列"视角（历年折线，带全球参照）；两者仍是报告材料的合法形态，并且在验收时能一眼找到。

**可以松动**：对比不必限定为恰好两国（2–5 国，或一国与全球参照）；对比不必是进入每个视角的前置条件（单国全貌、全体分布、行业结构都应能直接看）；时间序列不必是每一步的默认主图（可以是主题图，但历年视角一键可达）；实体的类型（国家、国家×行业、同一国家的多个行业）；步骤 9 的独立实现。

报告叙事相应调整为："所看实体（含对比国家时注明比较）+ 全球参照"，对比国家存在时仍按现在的写法逐国写变化与排名；不存在时写单国变化与全球位置。这样雇主要求的"对比"在报告里不会消失，只是不再作为唯一前提。

## 4. 重构方向

### 4.1 契约层：材料 = 一张可复现的图

把材料从"两国配对读数"改成"图表规格 + 读数"：

```
material = {
  chart: { view, metric(s), scope: country | country-industry, years, entities: string[1..5] },
  observations: VizObservation[]   // 每个实体 × 年份 × 指标一条，缺失不补零
  reference: "global-median" | "same-industry-median" | null
}
```

门槛改为：实体 ≥ 1；若只有 1 个实体，必须带全球参照（当年或各年的分布统计已在报告端重算，不需要存）；实体 ≥ 2 时即为"国家对比"材料，保持现在的配对规则（所有实体的键集合一致）；其余不变。旧记录 `compared` 两国 + 配对读数天然满足新规则，不需要迁移。

报告渲染按 `entities` 画 N 条 series，`_rank_reading` 按实体逐个写排名；有对比国家时沿用"比较对象"段落，单实体时写"所看国家与全球位置"。

### 4.2 探索器：视角优先，实体可变

- 实体选择器：一个主国家 + 可选 0–4 个对比（chips，可删），替换"国家 A / 对比国家 B"两个下拉；"添加对比国家"始终可见，这是雇主要求的入口。
- 每一步固定两个必有视角：**历年变化**（时间序列，带全球中位数与中间 50% 带）和**国家对比**（同一指标、同一年份或同一时间段内多国同图）。视角栏顺序固定为"主题视角（默认进入）→ 历年变化 → 国家对比 → 其余"，两个必有视角在每一步都在第 2、3 位，不随步骤变化。
- 其余视角按步骤主题增减，每个视角自己声明需要的实体数量；材料卡只说"当前图表可记录/不可记录及原因"，不再把"选对比国家"当作全局前置条件。
- 取消"补充图表"这一层（见 4.6）：定位图成为各步的定位视角，排名并入国家对比，热力表并入步骤 9 的国家对比视角，国家级网络图改为"贸易伙伴"视角。图表只分视角，没有二级入口。

### 4.3 每步图表安排（按各自指标）

原则：每步的视角由该步自己的指标集与恒等关系决定；视角栏顺序按 4.2（主题视角默认进入，历年变化与国家对比固定在第 2、3 位）。所有视角支持 1–5 个国家（同图或分面），所有图配十字线或图元级悬停、图例悬停高亮、图下读数表（4.7）。颜色：国家按 `CAT` 固定顺序；构成分项按各步既有分项色；负值红色、TLS 灰色。

#### 步骤 6 · GVC 贸易流（WWZ 聚合项 + TLS）

指标：`gross_exports = DVAex + DVArt + DDC + FVA + FDC + taxsub`（六项，`taxsub` 可为负），份额 `FVA_share`、`DVAex_share`，合计 `EXDVA`；国家整体与国家×行业两级。

| 视角 | 图形 | 指标与编码 | 对比与时间序列 | 报告材料 |
| --- | --- | --- | --- | --- |
| 出口构成（默认） | 带符号堆叠条，每国一条；切换"金额／占总出口比例" | 六项分段，负分项（如 TLS）在零轴左侧；条右端标总出口 | 多国同刻度并排即对比；"历年"子视角改为每国一张堆叠面积小倍数（份额口径） | 六项 + 总出口，单年或历年 |
| 历年变化 | 多国折线 + 全球中位数 + 中间 50% 带 | 任一份额或金额指标，默认 `FVA_share` | 国家对比：同图多线；时间序列：本体 | 所选指标逐年读数 |
| 国家对比 | 当年全球分布条带（高亮所选国）+ 下方排名条（前 20 与所选国） | 默认 `FVA_share`；金额指标用对数刻度排名 | 对比：同一指标同一年多国位置；可切年份看排名变化 | 所选国当年读数 + 名次 |
| 来源定位图 | 散点：x = 总出口（对数），y = `FVA_share`；点大小不编码 | 回答"出口规模大的经济体外国含量是否更高"；高亮所选国，可连成 2016→2020 轨迹 | 对比：多国高亮；时间：轨迹 | 不记录（探索） |
| 行业结构 | 点图：45 个行业一行一点，按国家 A 排序，多国各一色点，竖线为该国国家整体值 | `FVA_share` 或任一份额；切到金额时为水平条 | 对比：同行业多点；点击行业进入历年变化 | 行业级读数（现有 country-industry 口径） |

#### 步骤 7 · GVC 生产分解（WWYZ）

指标：前向 `SVA = 1_VA_D + 2_VA_RT + 3a_VA_GVC_S + 3b_VA_GVC_C`，四类份额加总 100%；后向 `FGY` 及其四类；份额 `3_VA_GVC_share`、`3b_VA_GVC_C_share`。

| 视角 | 图形 | 指标与编码 | 对比与时间序列 | 报告材料 |
| --- | --- | --- | --- | --- |
| 四类生产活动（默认） | 100% 堆叠条，每国一条；切换"前向（SVA）／后向（FGY）" | 纯国内、传统贸易、简单 GVC、复杂 GVC 四段，分段内标份额 | 多国并排即对比；"历年"子视角为每国一张四类份额堆叠面积小倍数 | 四类 + 总量，单年或历年 |
| 历年变化 | 多国折线 + 全球带 | 默认 `3b_VA_GVC_C_share`，可选任一份额或金额 | 同上 | 逐年读数 |
| 国家对比 | 分布条带 + 排名条 | 默认复杂 GVC 份额 | 同上 | 当年读数 + 名次 |
| 参与定位图 | 散点，两组坐标轴可切：① x = 简单 GVC 份额，y = 复杂 GVC 份额（参与方式）；② x = 前向 GVC 份额，y = 后向 GVC 份额 `3_FGY_GVC/FGY`（供给侧 vs 需求侧参与） | 四象限标签沿用现有文案；高亮所选国，可显示轨迹 | 对比：多国高亮；时间：轨迹 | 不记录 |
| 行业结构 | 一国 45 个行业的 100% 堆叠水平条，按复杂 GVC 份额排序 | 回答"哪些行业嵌入最深"；多国为分面 | 对比：分面；点击行业进入历年变化 | 行业级四类份额 |

#### 步骤 8 · GVC 长度与位置

指标：前向 `PLv` 与三段 `PLv_D`、`PLv_RT`、`PLv_GVC`，后向 `PLy` 与三段；位置 `GVCPs = PLv_GVC / PLy_GVC`、`Pos_TPL = PLv / PLy`。段长度不可相加（总长度是份额加权平均），因此不用堆叠图。

| 视角 | 图形 | 指标与编码 | 对比与时间序列 | 报告材料 |
| --- | --- | --- | --- | --- |
| 前后向位置（默认） | 轨迹散点：x = `PLy_GVC`，y = `PLv_GVC`，等长线 y = x；每国一条 2016→2020 连线轨迹，当年全部经济体为灰点云 | 线上方更偏上游；点上标年份 | 对比：多国轨迹同图；时间：轨迹本体 | 两段长度逐年读数（现有 directions 材料） |
| 段长度对照 | 哑铃图：三行（纯国内、传统贸易、GVC），每行前向点与后向点用线相连 | 一眼看出哪一段、哪个方向更长；多国分面 | 对比：分面；可切年份 | 六段读数 |
| 历年变化 | 小倍数：上图前向／后向 GVC 段长度多国折线，下图 `GVCPs` 折线带基准线 1 | 全球带与中位数同现 | 同上 | 逐年读数 |
| 国家对比 | 分布条带 + 排名条 | 默认 `GVCPs`，基准 1 标注 | 同上 | 当年读数 + 名次 |
| 行业结构 | 一国 45 个行业的位置散点（x = `PLy_GVC`，y = `PLv_GVC`，等长线），点可标行业代码 | 回答"本国哪些行业偏上游"；多国分面 | 对比：分面；点击行业进入历年变化 | 行业级读数 |

#### 步骤 9 · 生产网络（国家×行业网络指标）

指标：流量类 `weighted degree / indegree / outdegree`，拓扑类 `degree / indegree / outdegree`、`betweenesscentrality`、`closnesscentrality`、`harmonicclosnesscentrality`、`Eccentricity`、`eigencentrality`。无权指标在国家级退化为常数，所以所有图以国家×行业为单位，全球参照为"全部经济体同一行业"。

| 视角 | 图形 | 指标与编码 | 对比与时间序列 | 报告材料 |
| --- | --- | --- | --- | --- |
| 流量与拓扑（默认） | 散点：x = 加权总度（对数），y = 全正边二值介数；一国 45 个行业为点，标行业代码 | 直接回答本步的问题"流量规模与拓扑位置是否讲同一个故事"；多国分面或双色 | 对比：分面／双色；可切年份 | 不记录（探索） |
| 历年变化 | 一个行业的多国折线 + 同行业全球带 | 任一网络指标，默认加权总度 | 同上 | 逐年读数（现有） |
| 国家对比 | 当年同行业多国排名条 + 全球同行业中位数刻度；可展开为"全部指标表"（原热力表） | 默认加权总度；表格可按任一指标排序 | 对比：本体；切年份 | 当年行业读数（现有 ranking 材料） |
| 买入与卖出 | 蝴蝶图：每行一个行业，左为加权入度（买入），右为加权出度（卖出），按总度排序 | 回答"这个行业更多是供给方还是需求方"；多国分面 | 对比：分面；切年份 | 入出度读数 |
| 贸易伙伴 | 自我中心图 + 伙伴榜 + 区域流向矩阵（4.6） | 国家级双边流量 | 对比：并排两幅；时间：伙伴集中度折线 | 不记录 |

### 4.4 把步骤 9 并入同一框架

把网络指标做成第四个 `IndicatorTopic`（scope 固定为国家×行业，参照为同行业中位数），复用探索器的实体选择、视角、口径、记录和锁定逻辑，删掉 `network-trend.tsx` 中重复的部分，只保留步骤 9 专属的视角（流量与拓扑、买入与卖出、贸易伙伴）和全部指标表。

### 4.5 UI/UX 具体改进（与契约是否改无关，可先做）

- 控件分三组并固定顺序：实体 → 视角 → 范围（年份/行业/指标）；视角切换不再增减控件位置。
- 口径条做成粘性摘要卡（实体 · 范围 · 指标 · 年份），点击项可直接改。
- 读图卡（现有 `TrendSummary`/`ComparisonSummary`）统一到所有视角，每张图下都有"本国变化 → 全球位置 → 与对比的差距"三句。
- 空态与引导：首次进入显示本步推荐视角与一句"看什么"，而不是一张默认两国图。
- 对比国家为空时不出现警告色文案，材料卡用中性语气说明记录内容；但"添加对比国家"按钮和"国家对比"视角始终可见，验收时能直接指出。
- 保持现有的可访问性资产：`aria-label` 口径、`LabeledControl`、焦点管理、键盘可达的对话框（提交回执、确认框），这些在本周验收里是通过 WCAG A/AA 检查的，重构时作为回归项。

### 4.6 取消"补充图表"

现在步骤 6–9 各有一到两张图放在弹窗里（`chart-modal.tsx` 的 `SupplementaryCharts` / `ChartModalButton`，步骤 9 的网络图另有全屏遮罩）。弹窗是二级入口，关掉就回到两国主图，学生很少停留；而且"主图记录材料、弹窗不记录"这条规则本身就需要解释。改法：图表只分"视角"，每张图要么成为视角，要么并入某个视角，要么删掉。

| 现有补充图 | 步骤 | 处理 |
| --- | --- | --- |
| 定位图 `QuadrantScatter`（全部经济体双指标散点，高亮所选；选行业时为两国同行业） | 6–8 | 升为各步的定位视角（步骤 6 来源定位图、7 参与定位图、8 前后向位置），范围（国家整体／行业）沿用现有控件 |
| 排名 `RankBarChart`（前 20 与所选国家） | 6–8 | 并入"国家对比／全球分布"视角：分布条带下方直接给排名条，不再单独存在 |
| 行业热力表 `HeatTableViz`（单国全部行业 × 多指标，可排序） | 9 | 并入步骤 9 的"国家对比"视角（原定位行业）："显示行业"从 Top 10／全部扩展为"全部指标表"，排序沿用 `HEAT_SORT_OPTIONS` |
| 贸易网络图 `NetworkViz`（国家级有向网络，节点按区域摆放，边按阈值显示） | 9 | 不再整幅展示节点连线图，改为"贸易伙伴"视角，见下 |
| `chart-modal.tsx`、`SupplementaryCharts`、`ChartModalButton`、网络全屏遮罩 | 6–9 | 删除；验收脚本中点"贸易联系概览"与网络节点的步骤同步改写 |

**步骤 9 网络图的替代方案。** 国家级贸易图接近完全图，整幅节点连线图是一团线，真正可读的只有三样信息：某国的主要伙伴、区域内与区域间的流向、以及"国家级无权中心性没有区分度"这个教学点。建议用一个"贸易伙伴"视角承载这三样，全部可以复用现有数据与代码（`/api/viz/network/{year}` 的 nodes/edges，`trade-network.tsx` 里的 `thresholdedNetworkModel`、伙伴流量汇总与点击查看伙伴表）：

1. **自我中心图**：所选国家居中，按流量取前 N（默认 8）个伙伴排成一圈，角度按地理区域分组，半径固定，边宽表示金额，箭头表示"卖给谁"。选了对比国家就并排两幅、同一刻度，这正是硬需求里的国家对比。每个伙伴节点是按钮，带"伙伴、流入、流出"的无障碍文本。
2. **伙伴榜**：出口去向、进口来源两列水平条（前 10），是键盘与读屏友好的主要读数来源，也是这个视角的读数表。
3. **区域流向矩阵**：按预设地理区域把 76 个经济体聚合成一个小矩阵（行为卖方区域，列为买方区域，颜色为金额），一眼看出区域内与区域间流向。原图"节点按区域摆放"想表达的就是这件事，矩阵表达得更清楚也更可访问。

时间序列方面，该视角提供"伙伴集中度"（前 5 伙伴占比）和对主要伙伴流量的 2016–2020 折线，与硬需求对齐。教学点以一句固定说明保留："国家级网络接近完全图，介数等无权中心性没有区分度，所以本步的网络指标在国家×行业网络上计算"，并写进步骤 9 的理解题提示。

报告材料建议：阶段 0／1 先把"贸易伙伴"作为探索视角，不记录材料，报告材料仍来自行业视角，避免扩大报告契约；若之后要让伙伴读数进报告，再以 `entity = 国家·伙伴`、`metric = 流量` 的形式纳入 4.1 的材料规格。

### 4.7 悬停交互与图表库选型

**现状诊断。** 前端没有任何图表库（依赖只有 react、react-dom、react-markdown、remark-gfm），全部图表是手写 SVG：`viz/explore/charts.tsx`、`labs/steps/viz/indicator-charts.tsx`、`viz/views/trade-network.tsx`、`viz/regression/charts.tsx`、`report-renderer.tsx` 合计约 120 个 SVG 图元标签、2,000 行左右。项目其实已经有一个悬停层：`viz/shared.tsx` 的 `useTip()`（深色浮动提示，DOM 用 `textContent` 构造，随鼠标定位），定位图、排名条、构成条、回归系数图、贸易网络图都用它。**缺"交互感"的恰恰是步骤 6–9 的主图**：`indicator-charts.tsx` 里的历年折线、全球分布条带、配对柱、位置轨迹只用了 SVG 原生 `<title>`，表现为悬停约一秒后弹出浏览器默认提示、没有高亮、没有十字线、没有同一横坐标下全部序列的读数、键盘聚焦没有等价信息。所以根因不是"没用图表库"，而是最新这批图跳过了项目自己的悬停层，而且这个悬停层本身也只做到了"浮动提示"，没有十字线、高亮和焦点对等。

**目标交互（按 dataviz 规范，作为验收标准）**

- 折线类（历年变化、位置轨迹、伙伴集中度）：竖向十字线跟随并吸附到最近年份，一个提示框列出该年全部序列的读数，数值为主、序列名为辅，行首用序列色短线；悬停某条序列时其余序列减淡。
- 条、点、格类（对比柱、排名条、分布条带、定位散点、构成分段、区域矩阵）：图元自身是命中目标，命中区域不小于 24 px 或用最近点规则；悬停图元"抬起"（描边或提亮）并显示类别与数值；分段条显示分项占总量的比例。
- 键盘：所有命中目标可聚焦，聚焦显示与悬停相同的提示；Esc 关闭。
- 提示只做增强，不做门槛：每个值仍在图下读数表里可得（现有做法保留）。
- 图例可悬停：高亮对应序列，其余减淡；点击可隐藏/显示序列（可选）。

**选型比较**（约束：React 19 + Vite + Bun 单测用 happy-dom；报告正文的图由 JSON 块在 `report-renderer.tsx` 里渲染成静态 SVG 并打印成 PDF；生产 CSP 为 `script-src 'self'`，库必须打进 bundle；local_ci 对学生页面跑 WCAG 2 A/AA 自动检查；桌面 ≥1200 px）

| 方案 | 悬停能力 | 可访问性 | 与现有代码／测试／打印 | 体积与风险 | 结论 |
| --- | --- | --- | --- | --- | --- |
| A. 手写 SVG 补齐悬停层（自写 `useCrosshair`、命中目标、高亮/减淡、焦点对等；可选 `@visx/scale`、`@visx/event`、`@visx/voronoi` 做最近点） | 能达到上面全部目标，但动画要自己写 | 完全可控，沿用现有 `aria-label`、表格视图 | 零迁移；报告渲染、测试、验收脚本不变 | 不加或只加几十 KB；风险是继续维护一套自有图表代码 | 首选，先做 |
| B. Recharts 3（React 声明式 SVG，内置 Tooltip/十字线/activeDot，`accessibilityLayer` 支持键盘走读提示） | 折线、柱、散点开箱即得；十字线与多序列读数是默认行为 | 内置键盘走读；DOM 是 SVG，axe 可检查，但需补 `aria-label` | 标准图形迁移成本中等；分布条带、带负分项的构成条、位置轨迹、区域矩阵这类定制图仍要手写，形成两套风格；`ResponsiveContainer` 在 happy-dom 需要 ResizeObserver 垫片；报告静态 SVG 仍走现有渲染器 | 约 +100 KB gz；动画默认开启需关或调 | 若阶段 2 的新图（堆叠面积、小倍数、斜率图）数量多，可作为标准图形的库；先用阶段 0 的试点评估 |
| C. Apache ECharts（`echarts/core` 按需引入，canvas 或 SVG 渲染） | 最强：axisPointer 十字线、`trigger: 'axis'` 多序列提示、emphasis/blur 焦点态、过渡动画、中文文档 | 弱：canvas 对 axe 不透明，SVG 渲染器输出的 path 无语义，没有键盘走读；`aria` 选项只生成一段描述和纹理 | 图表变成黑盒，现有按 `.network-node[aria-label]`、`svg[role=img]` 的验收脚本与测试要重写；报告打印需另走一条路径 | 约 +180 KB gz；与本项目"可访问性 + 可打印 + 可测试"的既有投资冲突 | 不建议作为试点 |
| D. visx 全量替换 / Nivo / Observable Plot / Vega-Lite | visx 等于方案 A 的工具箱；Nivo 带 react-spring 偏重；Plot 与 Vega 是命令式或运行时方案，与 React 组件、测试、CSP 契合度低 | 各异 | 迁移成本高于收益 | — | 不考虑 |

**建议。** 把"交互感"当作悬停层的缺失来修，而不是图表库的缺失：

1. 阶段 0 内先做共享交互原语（`useCrosshair`、`HitTarget`、序列高亮/减淡、焦点对等的提示），给 `indicator-charts.tsx` 的四类主图和 `useTip` 已覆盖的图统一接上；这是 2–3 天的工作，不动契约、不动测试结构，验收脚本只需加"悬停后出现提示框"的断言。
2. 同时做一个 1 天的试点：用 Recharts 重做步骤 6 的历年变化图（带中间 50% 带、全球中位数虚线、多国序列、十字线读数），与方案 A 的同一张图并排比较：交互手感、代码量、axe 结果、happy-dom 单测、bundle 增量。试点结果决定阶段 2 的新图用 Recharts 还是继续手写。
3. 不选 ECharts，除非接受"学生端图表不可被自动可访问性检查、键盘不可走读、报告图另做一套"这三条代价。

**试点结果（2026-10-06）。** `frontend/src/labs/steps/viz/indicator-trend-recharts.tsx` 用 Recharts 3.10 重做了步骤 6 的历年变化图（中间 50% 带、全球中位数虚线、多国序列、十字线读数、图例减淡）；地址加 `?pilot=recharts` 时它懒加载在手写图下方并排显示，不记录材料。对照同一数据：

| 比较项 | A. 手写 SVG（阶段 0 共享悬停层完成后） | B. Recharts 3.10 试点 |
| --- | --- | --- |
| 交互手感 | 十字线吸附年份、全序列读数、图例悬停减淡、焦点放大点；无动画 | Tooltip、cursor、activeDot 开箱即得，手感相当；中间 50% 带要用 Area 的区间数据，图例减淡与读数格式仍要自写 Legend／Tooltip 的 content |
| 键盘 | 容器 tabIndex=0，方向键逐年、Home／End、Esc 关闭 | `accessibilityLayer` 默认开启：svg 为 role="application"、tabIndex=0，方向键移动提示；没有 Esc 关闭；每个 zIndex 图层另带 `<g tabindex="-1">`（15 个） |
| 代码量 | `IndicatorTrendChart` 约 260 行（含键盘、图例、命中区、读数卡接线） | 约 190 行，其中约 90 行是数据整形、图例与提示框改回项目格式 |
| happy-dom 单测 | 6 例通过 | 固定 `width` 可渲染并测键盘与图例减淡（3 例通过）；`responsive` 依赖 ResizeObserver，happy-dom 没有 |
| 可访问性 | svg role="img" + aria-label，读数表 | svg 的 title／desc 由 props 生成；role="application" 使读屏进入应用模式；本次未跑 axe |
| bundle | 0 | 独立懒加载 chunk 391 KB（gzip 114 KB），与现有 index chunk（gzip 115 KB）相当；Recharts 3 带 redux、d3-shape／scale 等依赖 |
| 报告打印 | 同一渲染器 | 不适用，报告仍走 `report-renderer.tsx` |

结论：悬停层做完之后，手写图在交互与键盘上已与 Recharts 持平；Recharts 对本项目的定制图（分布条带、带负分项的构成条、位置轨迹、区域矩阵）没有帮助，代价是学生端 JS 体积翻倍和两套视觉。阶段 2 的新图继续手写（方案 A），在共享悬停原语上扩展；试点代码留在 `?pilot=recharts` 开关后面供对照，阶段 2 开始前移除 `recharts` 依赖。

无论哪条路，颜色沿用现有 `CAT` 顺序与负值红色、TLS 灰色约定，新加的图表在动手前跑一次 dataviz 的调色板校验脚本（adjacent-pair CVD 分离度），避免为了交互重做颜色。
