## 2. 不可越过的边界

1. 仅覆盖 **CSS 视口宽度至少 1200 px 的桌面浏览器**。主路径 1440×1000，边界 1200×800，宽屏 1920×1080；不增加手机、平板、窄屏适配任务。大表格可在明确的局部滚动区域内横向滚动。
2. 真实浏览器操作一律使用 `agent-browser`，按角色/场景隔离命名 session；每次页面变化刷新 snapshot。DOM 读取辅助验证，不用注入 React 状态、写 localStorage 或 API 预填去假扮学生完成任务。
3. 原课堂 8000、其数据库、`/opt/gvcsim` 数据与认证材料均不作为写入/故障/压力测试目标。
4. 共享 PostgreSQL 5432 同时承载课堂服务。**独立数据库不等于独立 PostgreSQL 进程**：禁止为了测恢复而停止它；进程故障须另建私有 PGDATA 和端口。
5. `tests/conftest.py::teaching_db` 会删除 public schema。后端全量单测使用另一套一次性库/角色，明确两种 DSN；既不用课堂库，也不用保留 Dogfood 证据的开发库。
6. 文件损坏、原子发布切换、权限异常只对另一份临时 raw/release 副本操作。数学小样本/无效发布夹具不替换常驻开发实例的真实数据。
7. 不用 `sleep`、调整系统时钟、放宽数值精度或移除推断门禁让测试通过；等待可观察状态，竞争测试用事件/屏障制造确定顺序。
8. 本轮先探索、记录和二次复现，再单独修复。不能边改热加载代码边宣称整轮仍基于同一提交；修复后另记版本、复验结果。
9. HAR、认证状态、下载内容、截图和 DB 查询输出先脱敏；不要记录密码、Bearer token、签名密钥或完整 DSN。

### D. 故障恢复、文件缓存与发布（另建临时实例）

- D01：浏览器离线/慢响应/503；保存、切片、回归、报告均应区分加载/失败/重试，恢复后不复用错误状态。
- D02：在拥有的 API 子进程上执行优雅重启/取消风暴，记录线程、任务、令牌、队列和迟到异常；同步工作结束前容量不得虚假释放，关闭池前先回收。
- D03：**私有 PostgreSQL 集群**暂停、断连接、事务 abort、恢复；核对最后一次可见提交及重试语义，不停共享 5432。
- D04：独立 raw/release 副本中做等长覆盖、固定 stat、原子替换、读取中修改再恢复、来源不符；hash 模式必须拒绝坏数据且不返回旧快照。
- D05：如评估 notify，另行明确模式、文件系统及不变性假设，覆盖通知故障/溢出/回退；不把 mmap 不可覆盖的优化承诺成默认安全保证。
- D06：独立发布切换/回退，报告与课程版本交错；禁止混合新旧文件，来源绑定及版本门禁不能绕开。历史报告保持自己的证据版本。

故障用例先验证端口、PGDATA、目录和 PID 所有权，再注入；结束恢复并核查无孤儿线程/进程、临时 DB/角色/副本残留。不能为了“失败截图”在常驻开发环境破坏主旅程证据。

### E. 桌面可用性、可访问性与性能

- E01：1200/1440/1920 px 分别检查 15 步、教师表格/弹窗、长公式/长标签；固定头尾不遮挡操作，局部表格滚动不演变为全页溢出。
- E02：仅键盘完成核心路径；焦点可见、对话框焦点管理/Escape、跳到主内容、原表方向键/Enter/Tab、图表替代文字、错误反馈关联。自动化 accessibility 结果不等同于完整 WCAG 合规。
- E03：空态、错误态、长中文、零值/负值/NaN、多个图例/颜色和图标字形；实际查看截图，不只检查 DOM 宽度。
- E04：记录冷/热原表、指标、回归、教师列表和报告延迟，CPU/RSS、错误/取消数量。区分前端 dev/StrictMode、后端 reload、hash I/O 和真正业务延迟。
- E05：需要容量结论时，另开无 reload 的专属后端、生产前端及对应代理，再按 1→5→10→25→50 并发分档测同键/不同键负载；每档记录请求数、分位延迟、503、队列和资源。与课堂共享主机时先限额/安排窗口；无足够隔离就将 25/50 人压测标为未执行，不冲击课堂进程。

不从开发服务器单次观测推断课堂 SLA；历史 Nginx/50 人结果也不直接沿用到本次 hash 模式。

| 已有 seeded 快速旅程 | `scripts/agent_browser_full_journey.sh` | **会预填学习记录**，只能作辅助，不能替代 A |
| 可访问性 | `scripts/agent_browser_course_accessibility.py` | 仅桌面；自动扫描后人工核对焦点、表格及屏幕文案 |
| 独立 raw 数值参照 | `scripts/dogfood_raw_oracle.py` | 后半段会 seed 报告前置记录；不能冒充真实主旅程。本轮另用只读 oracle，明确指向开发副本，区分抽样检查与全量重算 |
| HTTP/同步/交错 | `scripts/dogfood_http_edges.py`、`dogfood_sync.py`、`dogfood_workspace_interleavings.py` | 各用独立账号/状态；不得沿用 8000 默认值 |
| 报告/认证恢复 | `scripts/dogfood_report_snapshots.py`、`dogfood_self_password_recovery.py`、`dogfood_token_expiry.py` | 使用可丢弃账号和实例；不修改全局时钟或常驻实例密钥 |
| 发布/事务/进程故障 | `scripts/dogfood_release_roundtrip.py`、`dogfood_publication_faults.py`、`dogfood_transaction_abort.py`、`dogfood_process_faults.py`、`dogfood_fault_proxy.py` | 核对私有目录/PGDATA/端口/PID 及清理逻辑；不直接对常驻环境运行 |

这些是**候选工具，不是已经运行的结果**。每个脚本执行前完整读入口、默认值、环境变量、是否 seed/reset/stop service；以当前实现为准，不盲跑历史命令。单元回归需要另设测试 DB：前端正确入口是 `cd frontend && bun run test:unit`，后端必须显式隔离后才跑全量。

## 6. 证据格式、缺陷标准与退出条件

每个用例记录：ID、执行状态（未执行/通过/失败/阻断/不适用）、commit/dirty 状态、release、缓存模式、数据类型、角色/账号、视口、操作/预期/实际、时间、证据路径。

每个候选问题先至少复现两次；尽量换干净会话或账号确认。交互问题保留 `agent-browser` 录屏和步骤截图；静态视觉问题用足够定位的截图；数值问题保存输入、独立参考、误差及 API/报告片段；并发问题保留可重放时序，不能只有“偶尔发生”。先定位层级再归责，不把工具超时、测试夹具错误或不支持的布局当产品缺陷。

分级按真实影响：阻断主旅程/数据丢失/越权、错误经济学结论或持久化错配优先；普通交互/布局问题其次。已修复旧问题、明确教学简化、文案建议、环境问题和不可复现线索分栏，不重复计入新缺陷。

退出条件：

1. A 的 15 步真实学生旅程和教师闭环有可核对证据；不能完成则明确列阻断，不假报通过。
2. B/C 高风险场景和 ER01–ER04 有本轮结果；所有抑制推断的设计继续抑制，报告忠实传播结果/原因。
3. 支持的桌面尺寸完成关键视觉/键盘检查；无未说明的崩溃、串账号、静默丢写或公式误导。
4. D/E 每项明确完成范围与未执行原因；没有隔离环境的压力/故障用例不勉强执行。
5. 发现已确认问题时，先出复现报告，再另批修复和回归；完整单测/构建结果与真实浏览器结果分别统计，不冒充互相覆盖。
6. 收尾关闭测试浏览器/故障子进程、清理临时测试库/角色；保留常驻开发服务、主旅程开发库和脱敏证据，除非另有停止/删除要求。

最终输出：测试摘要、逐项覆盖表、按严重性排序的可复现问题、证据目录、经济学数值核对表、剩余风险/未执行项。**本文是计划，不是全量验收结论。**
