# 文件时间戳碰撞与缓存身份修复（2026-09-08）

## 结论与范围

这是 `6f6e496` 之前已经存在的独立问题，不是普通 I/O 取消修复引入。三项历史失败不能全部解释成无害的测试抖动：

- 原子替换测试同时要求 inode 与 ctime 改变，后者并非缓存失效的必要条件；保留 inode 变化和拒绝坏 CSV 的功能断言。
- 同大小原地覆盖并恢复 mtime 时，ctime 也可能落在同一文件系统时间戳粒度内。`*_ns` 表示纳秒单位，不保证每次写入生成唯一版本。旧实现可能复用 CSV、发布校验、原始来源 SHA-256 证据和浏览表的缓存。

用夹具固定 `Path.stat()` 返回值，先在未修复实现上得到 **7 失败、3 通过**，覆盖发布 metadata／产物、普通 CSV、原始身份、严格校验、来源绑定和浏览缓存。这里没有用 sleep 等待时间戳变化。

本次没有修改数值算法、数据发布格式、artifact contract、数据库 schema 或课堂事务。

## 默认内容哈希模式

新增 `gvcsim/file_identity.py`，把文件身份统一为 stat 字段加独立的内容／变更标识，接入：

- `dataset.json`、发布完整性缓存、普通 CSV；
- 原始 ICIO 严格校验、来源哈希、双边出口、浏览 metadata 与完整表；
- 出口暴露度索引和可选政策事件目录。

`GVCSIM_FILE_CACHE_MODE=hash` 是默认值。每次取得文件身份都实际读取 SHA-256，不复用按 stat 缓存的哈希。因此，stat 全部相同的改写，包括 mmap 修改，也会形成不同的缓存键。

仅在解析前后比较哈希仍可能遇到“文件临时改写、解析到了新内容、随后恢复旧字节”的竞争。hash 模式的缓存解析器使用与键中摘要一致的不可变字节快照，避免把新内容放入旧键；原始来源证据还要求其实际摘要与身份中的摘要一致。读取／验证完成后再次检查身份，发现变化时拒绝并不缓存本次结果。

代价是每次身份检查的流式哈希 I/O／CPU，以及缓存未命中时一个文件的解析快照内存。它保证内容身份，不提供多文件事务或对持续外部写入的可用性承诺；数据发布仍应在停止 API 的维护窗口完成。

## 只读本地部署的通知优化

`GVCSIM_FILE_CACHE_MODE=notify` 显式选择 Linux inotify 优化，`deploy/gvcsim-api.service` 在只读数据沙箱内设置此值：

- 仅对白名单中的 ext 系列、tmpfs、XFS、Btrfs 启用；未知文件系统（包括网络文件系统）回退实际哈希，不假设远程改写会产生本地通知。
- 每次查键同步注册当前 inode 并消费队列，普通写入、属性变化、原子替换及通过硬链接的写入均能使旧键失效；无轮询间隔，无后台线程。
- 只保留一个非阻塞描述符和最多 1024 个 inode watch；超额文件回退哈希，不轮换所有 watch 导致大型目录永远无法稳定验证。
- 通知队列溢出后重建描述符和版本；注册／读取失败回退哈希，不能沿用旧 stat 键。一次队列读取最多 16 批，持续写入不能无限占用请求线程。
- fork 子进程重建锁和通知状态，不能与父进程竞争同一个事件队列；退出时关闭描述符。
- 热缓存身份与原始来源证据复用不重新打开源文件；文件读取、计算和 single-flight 的既有限额保持不变。

**notify 不监控 mmap／原始块设备写入，不能替代不可变数据的部署边界。** API 与外部维护程序都不得在运行期改写 active release 或原始输入；有不受通知覆盖的修改可能时必须保留 hash。systemd 的只读沙箱只约束服务进程，不能证明外部写入不存在。

`/etc/gvcsim.env` 中显式写 `GVCSIM_FILE_CACHE_MODE=hash` 可覆盖服务模板。非法模式值直接报错；修改变量后需重启进程。CLI／独立脚本未设置该变量时始终使用 hash。

## 验证

新增／加强的用例同时覆盖 hash 与 notify：固定 stat 的连续写入、原子替换、硬链接、mmap（hash）、读取中改写／恢复、缓存不可污染、来源证据、浏览器和派生索引。另有通知热路径、溢出、watch 上限、初始化／读取失败、持续事件流和 fork 重建测试。

最终验证结果：

| 验证 | 结果 |
| --- | --- |
| 碰撞／读取竞争／通知边界针对性测试 | 63 通过 |

完整后端使用独立临时 PostgreSQL 角色／数据库和临时 CI 合成 release 分别验证两种模式，全部临时数据库、角色与合成数据已清理。测试夹具会删除目标库的 `public` schema，不得使用课程数据库。root 执行时移除 DAC 读取权限绕过能力，不修改仓库权限。三个历史时间戳问题均已纳入本轮通过的回归覆盖，不再依赖文件系统时钟是否恰好前进。

## 部署

只需更新代码并重启 API；本次不需要 `compute`，更不需要 `classroom-init --reset`。只读本地部署若要保留通知优化，应同时安装新版 systemd 模板并执行 `systemctl daemon-reload`；只更新代码而不配置模式会采用更保守、I/O 成本更高的 hash。

本轮不执行线上部署、真实 OECD 数据的 50 人 HTTP 压测或数据重算。历史并发验收不能直接当作新缓存模式的实机容量验收；后续压测须记录所用模式并满足对应的数据不可变前提。
