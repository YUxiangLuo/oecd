# 最终全面深度测试规划（2026-10-10）

本轮测试面向雇主（经济学家）验收前的最后一次全面检查。范围是**功能、UI/UX、经济学内容**；安全、并发、负载不在范围内。演示服务器性能有限，全部测试在**本地环境**进行。

与第 10–25 轮不同，本轮测试**不以角色扮演为主**。前面十几轮都是让代理扮演学生点击页面，问题已经收敛。剩下的风险集中在这类测试做不到的地方：

- 数字没有被独立复算过。过去只核对了页面、报告、手册三者之间是否一致，这只能说明程序前后一致。
- 经济学表述没有被逐句审读过。
- 理解题没有逐题逐选项核对过。
- 数据中的边界情况只是偶然碰到，没有逐个检查。

本轮以这四类测试为主，角色扮演只保留两个代理。

## 2. 本地环境搭建

1. `CREATE DATABASE gvclab_r26`；以 `GVCSIM_DEMO_MODE=1` 执行 `gvcsim classroom-init`，再执行 `gvcsim preflight`。
2. 启动 API：`gvcsim serve --port 9500`，`GVCSIM_FILE_CACHE_MODE=notify`。
3. 构建演示版前端：`VITE_DEMO_PASSWORD` 取自本地环境，执行 `bun run build:demo`。用 `bun run preview --port 4493`，并设置 `GVCSIM_API_PROXY=http://127.0.0.1:9500`。
4. 以教师身份调用一次 `/api/regression/teaching-overview` 预热（冷启动约 11 秒）。
5. 后端测试只能用 `pytest-safe.sh` 运行：取消所有 `GVCSIM_*` 环境变量，数据库指向 `gvclab_cc_test`，名字必须以 `_test` 结尾。会话重启后临时目录会被清空，届时重建这个脚本。
6. 若测试中修改了后端代码，重新构建前端后**必须重启 API**。
7. 禁止使用 `bunx --cwd …`。
8. 任何代理都不得输入、打印、截图或读取密码；登录一律使用快捷登录按钮。

## 3. 测试项目

共 7 个代理。A–D 互不依赖，可以并行；E 需要一个完整的学生账号；F1、F2 最后进行。

### A. 数值独立复算（最高优先级）

**目的**：不读 `gvcsim/` 源码，只依据方法文献，用 pandas/numpy 从原始 ICIO CSV 复算，与 API 返回值比较。

**依据**：
- `frontend/public/readings/` 中的课程校订版说明；
- Wang、Wei、Zhu（2013/2018）、Wang 等（2017a、2017b）原文；
- `实验手册.md`、`技术手册.md` 中的公式。

**样本**：
- 国家：CHN、USA、DEU、MEX、VNM。
- 年份：2016、2020。
- 行业：C26、C29、G。
- 边界节点：MLT·H51（负增加值）、一个零产出节点。

**复算内容**：

| 指标族 | 复算内容 | 对照接口 |
| --- | --- | --- |
| 步骤 1 账户 | Z、Y、VA、TLS、OUT 的读数；行恒等式 OUT = Z 行和 + Y 行和 | `/api/db/slice` |
| 步骤 2 贸易分解 | WWZ 六项 DVAex、DVArt、DDC、FVA、FDC、taxsub 之和等于总出口；外国增加值项占比 | `/api/indicators/country/{year}`、`/api/indicators/industry/{year}` |
| 步骤 3 生产分解 | 纯国内、传统贸易、简单 GVC、复杂 GVC 四类及其份额；前向总 = 简单 + 复杂；后向（最终品）分解 | 同上（指标接口） |
| 步骤 4 长度 | PLv、PLy 及各段长度；PLy 等于各段按最终品份额的加权平均；GVCPs = PLv_GVC / PLy_GVC | 同上（指标接口） |
| 步骤 5 网络 | 度、入度、出度、加权入度/出度/总度；有条件时用 networkx 在同一边集上复算介数和接近中心性 | `/api/indicators/industry/{year}`、`/api/viz/network/{year}`、`network_edges_*.csv` |
| 步骤 10 关税暴露 | 2016 年对美货物（A–C）顺差 ≥ 1,000 百万美元，得出 37 个被加税国家；w = 首年对美出口份额；X = w × τ（τ = 25%，2018 年起） | `/api/regression/teaching-countries`、`/api/regression/teaching-panel` |
| 步骤 11–14 回归 | 对 `panel_teaching.csv` 做双向固定效应（国家×行业与年份），按国家聚类（CR1）计算标准误；复算每个 Y 的 β、标准误、95% 区间、标准差换算 | `/api/regression/teaching-overview`、`/api/regression/run` |

**容差**（与流水线自身 QC 的门槛一致）：
- 恒等式与分解：绝对误差和相对误差均为 1e‑8（`qc_outputs_*.json` 的 `trade_identities` 等）；
- X 比例：1e‑12（`shocks.py` 中的 `EXPOSURE_RATIO_*`）；
- 回归标准误：atol 1e‑10，rtol 1e‑6（`regression/benchmark.py` 的 `matched_cr1`）；
- 独立实现之间的浮点差异，放宽到相对误差 1e‑6，并在报告中写明原因。

**交付**：一张对照表，列出每个数值的独立复算值、API 值、差值，以及通过或不通过。全部复算脚本放在临时目录，并附在报告中。

### B. 经济学审读（以阅读为主，不点击页面）

**目的**：按审稿人的标准，逐句通读所有学生能看到的文字。

**材料**：
- `gvcsim/steps.py`（任务卡）、`gvcsim/quizzes.py`；
- `frontend/src/regression-lessons.ts`、`regression-verdict.ts`；
- `gvcsim/report_build.py`、`report_render.py`、`report_common.py`；
- `实验手册.md`、四份课程校订版 PDF；
- 页面上的方法卡片和图注。

**必须回答的问题**：
1. WWZ 各项、四类生产活动、PLv/PLy、GVCPs > 1 表示更上游，这些定义与原文献是否一致？全文是否前后一致？
2. "复杂 GVC 至少跨境两次"、"简单 GVC 随中间品跨境一次"的表述是否准确？
3. 回归部分是否全程只用相关表述，没有任何一句暗示因果？
4. 加税前后趋势图隐含了平行趋势的含义，而文字没有交代。是否需要补一句？
5. 标准差换算用的是混合样本（pooled）的标准差，而估计用的是组内变化。文字是否会误导？（第 21 轮经济学家视角的代理提出过）
6. "首年对美出口份额固定"作为 Bartik 式暴露度的构造，是否解释清楚？
7. 95% 区间的释义"真实系数的合理取值范围"：课程负责人已决定保留，本轮只记录，不作为缺陷。
8. 报告中的方法说明与局限是否完整，有没有提到没有用到的东西（例如宏观控制变量）？
9. 术语在页面、报告和手册三处是否统一？

**交付**：逐条意见，注明文件和行号、原文、问题、建议改法，以及严重度（高/中/低）。

### C. 理解题穷举

**目的**：逐题检查 15 个步骤的全部理解题：每个选项都提交一次，核对判分和提示。

**方法**：
- 用一个演示学生账号，通过页面或 API 提交（服务端判分）；
- 每题确认恰好有一个正确选项；
- 错误选项的提示合理，不泄露答案；
- 正确答案与页面上的实际数字一致，例如题目引用的数值在当前数据下是否成立；
- 干扰项在经济学上站得住；
- 措辞为书面语。

**交付**：一张表，列出步骤、题号、选项、判分、提示文字、问题。

### D. 数据边界情况逐个检查

**目的**：把会触发特殊处理的数据逐一找出，在页面上打开并截图核对。

**清单**（先从 release 文件中枚举全量，再全部检查）：
- 负增加值节点：`qc_*.json` 列出 ITA·C19、FIN/CZE/LVA/MLT·H51，生产份额应置空；
- 零产出节点：2020 年有 25 个；
- 行业 T（家庭自用生产）全为零；
- 某国某行业不出口（份额无定义）；
- 产品税减补贴为负的国家，用于检查负分项红色显示的说明是否出现；
- 被加税但 w = 0 的国家×行业（如 CHN·D）；
- 不在回归样本中的国家×行业（如 CHN·E/F、JPN·O）；
- 美国作为例子国家或对照国家；
- LUX 闲置行业；
- 行业数少于 45 的国家；
- 只选一个国家时的单个行业比较范围。

**交付**：每种情况的页面截图（已打开查看），页面说明是否准确，是否出现空图、NaN、"0.00"或误导性文字。

### E. 报告与页面的程序化核对

**目的**：用一个学生账号按固定选择走完全程，再用程序比对报告和页面上的全部数字，代替人工抽查的约 30 个。

**固定选择**：
- 步骤 2–5 选 DEU；
- 步骤 6–9 选 DEU、USA、CHN；
- 步骤 10 选 MEX、CRI、C29；
- 步骤 13 保存非默认 Y（后向 GVC 段长度）；
- 其余默认。

**方法**：
- 生成草稿后，解析报告 markdown 中的每一个数字（材料表、回归表、汇总表、附录、换算）；
- 与对应 API 返回值比较，按页面的显示位数取整后必须相等；
- 打印视图另存为 PDF，抽查 5 页版式。

**交付**：报告数字与 API 值的对照表，列出不一致之处。

### F2. 雇主视角与教师端（角色扮演）

经济学家第一次打开系统：先以学生身份浏览 15 步（不必完成），再看教师端三个视图。

**重点**：
- 第一印象是否专业，有无可以挑剔的经济学表述或数字；
- 教师端初次打开时是空的（没有学期、班级和示例报告）。由测试者给出建议：是否需要预置一份演示学期、班级和一份已批改的示例报告。**是否预置由课程负责人决定。**

## 4. 严重度定义

| 级别 | 含义 | 例子 |
| --- | --- | --- |
| 高 | 阻断操作、数字错误、误导经济学结论、数据丢失 | 复算值与页面不一致；理解题的标准答案错误；退出登录后无法切换身份 |
| 中 | 经济学家会注意到的不一致或含糊；明显的界面故障 | 同一术语在两处定义不同；图例描述了图上没有的元素 |
| 低 | 措辞与版式打磨 | 换行位置；小数位风格 |

## 5. 不在范围内

- 断网与重试（第 19–23 轮已测）；
- 多标签页冲突（第 21、23、25 轮已测）；
- 演示服务器本身。

## 8. 执行顺序与修复流程

1. 搭建环境（第 2 节），记录基线（第 1 节）。
2. 并行运行 A、B、C、D，再运行 E。
3. 运行 F1、F2。
4. 汇总、去重、分级。确有疑问的项目先请课程负责人决定。
5. 统一修复。每项修复都要有对应的单元测试；修改后端代码后重启 API。
6. 针对每一项修复做定向复测；A 与 E 的脚本重跑一遍，确认没有引入新的偏差。
7. 更新实验手册的截图与 PDF，以及评审记录 `docs/review-ux-copy-2026-10-08.md`。
8. 部署到演示站：校验上传文件、换用全新数据库、预热缓存。
9. 推送到 GitHub。
