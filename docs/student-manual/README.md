# 学生实验手册维护说明

- 成品：[实验手册.pdf](../../实验手册.pdf)，A4，27 页，19 张操作截图。学生在左侧“课程大纲”下的“实验手册 PDF”入口打开；前端直接引用这份 PDF，Vite 把它作为带内容指纹的静态资源打入构建，更新后重新构建前端即可发布。
- 正文：[实验手册.md](../../实验手册.md)，`<!-- page -->` 为显式分页点。
- 截图：[screenshots/](screenshots/)，来源清单 [screenshots.json](screenshots.json)（代码基线、数据 release、尺寸、SHA-256）。`tests/test_steps.py` 会核对清单中的哈希。
- 脚本：`frontend/scripts/` 下的截图、排版与导出脚本，使用本机 Chrome（可用 `CHROME_PATH` 指定）和中文字体（Linux 用 Noto Sans CJK SC，Windows 用 Noto Sans SC）。

## 重新生成

1. 在独立的本地课堂（Vite 开发服务器 + API）准备两个测试学生：一个完成步骤 1–14 且尚未生成报告（可用 `scripts/seed_full_journey.py`），另一个只做了一部分。截图脚本会为第一个学生生成、提交报告并由教师评分，所以只用测试账号。
2. 截图（账号只通过环境变量传入）：

```bash
MANUAL_STUDENT=<完整学生> MANUAL_STUDENT_PASSWORD=<口令> \
MANUAL_GATE_STUDENT=<未完成学生> MANUAL_GATE_STUDENT_PASSWORD=<口令> \
MANUAL_TEACHER=<教师> MANUAL_TEACHER_PASSWORD=<口令> \
  bun run frontend/scripts/capture-student-manual.ts
```

3. 排版并导出；导出前逐页检查正文是否超出 A4 版心，超出时报出页码与像素：

```bash
bun run frontend/scripts/build-student-manual.ts
bun run frontend/scripts/export-student-manual.ts
```

截图脚本把每张图的尺寸与 SHA-256 写到 `dogfood-output/student-manual/capture.json`，据此更新 `screenshots.json`。

## 更新时核对

1. 截图只用独立测试账号，不含密码或真实学生信息；用公开 API 预填学习记录时在来源清单中写明。
2. 正文的按钮名、条件、截图说明和数据口径与当前界面一致；不要用新说明解释不匹配的旧截图。
3. 页数变化时，同步正文导航表的页码和本说明的总页数；手册封面与末页的版本说明同步更新。
4. 截图中的评分只说明流程，不构成评分标准。
