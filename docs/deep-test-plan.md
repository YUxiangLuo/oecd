深度测试计划（基于 49c7af1，首批已执行）

本计划承接 2026-09-07 Dogfood 验收。已有 556 项后端、355 项前端测试，以及真实浏览器、API、并发和备份恢复基线；这些结果不能代替下面的新增验证。首批七项执行结果见 [P0 测试结果](p0-test-results.md)；其余项目仍待执行，未宣称全部计划完成。SSH 恢复后再根据 SERVER-ENVIRONMENT.md 补充远程环境差异。

测试以数据不丢失、不串账号/版本、报告证据一致、数值含义正确、故障后可恢复为主要目标。覆盖率作为定位盲区的辅助指标，不以提高百分比或增加重复用例作为完成条件。沿用项目桌面端支持范围；不增加移动端适配、多 worker 支持、离线自动合并、考试防作弊等产品能力。

优先级：P0 为数据、权限、版本或报告正确性；P1 为教学闭环、数值核验与容量；P2 为长期稳定性和环境差异。已有单测的情景优先补真实进程、真实 PostgreSQL 或真实浏览器证据，不简单复制断言。

对两个操作会相互影响的 P0 情景，使用数据库行锁、代理控制点或仅测试使用的屏障固定时序。必须覆盖关键交错顺序；不能靠随机 sleep 碰巧复现。记录请求 ID、账号、release、基础版本、提交结果、数据库最终状态与浏览器所见内容，但不记录密码或认证令牌。

状态组合按风险组织：账号（未登录/学生/教师）、会话（空/已保存/保存中/未保存/冲突/恢复待处理）、报告（无/草稿/待评阅/已评阅）、网络（正常/延迟/中断/提交成功但响应丢失）、release（原版本/新版本/回滚）。P0 明确枚举危险交错，其余采用成对组合与有固定种子的随机操作序列；发现失败后缩减为最短可重放序列。合成数据用于触发少见结构，真实五年数据用于完整流程和性能，不能互相替代。

执行顺序和产出：

1. 先补测试基础设施：独立数据库/数据副本、可控响应丢失和阻塞点、统一证据脱敏、确定性测试账号、数据库与 UI 状态对照。将上一轮有价值的临时脚本整理成可维护测试，去掉固定个人路径、凭证和“取表格第一行”之类脆弱定位。
2. 先跑 SYNC/AUTH/REPORT 的 P0 时序矩阵，再跑数据库/进程故障；把“保存成功但响应丢失”作为首个案例。每个问题先独立复现两次，再修复、加入最小回归并重新检查原场景。
3. 完成 E2E/DATA：至少一条纯浏览器全课程路径，以及一条含错答、改选、无效回归和报告重生成的恢复路径；逐层核对关键数据来源。
4. 跑发布中断、换版回滚、备份恢复；这些操作只在隔离环境执行。对所有候选发布完成完整性预检。
5. 测容量分布和课堂混合负载，通过后先 2 小时持续运行，再做过夜测试；长测前保留当前稳定基线，并设定自动结束/资源上限。
6. SSH 恢复后先读环境文档、比对差异，仅补远程相关检查；未经该步骤不宣称远程部署通过。

第一批执行固定为 SYNC-01、SYNC-02、AUTH-02、REPORT-01、REPORT-02、FAIL-01、E2E-01。这批优先发现最难补救的学习记录丢失、跨版本恢复和报告错配问题。长时间压测在这批通过后开始，避免把稳定可重现的状态机问题淹没在负载噪声里。

持续集成分层：每次提交跑确定性的核心状态机/输入/数值回归；夜间跑真实 PostgreSQL 故障场景、更多随机种子与纯浏览器旅程；发布前跑真实五年数据、冷启动分布、发布/回滚和恢复演练；过夜测试独立计划运行。耗时任务不一股脑塞进每次提交检查。

验收要求：所有 P0 案例通过、无未解决的数据丢失/越权/跨版本混入/报告错配；每个新增缺陷都有二次确认及修复后的实际场景证据；合法操作无非预期 500，预期拒绝准确归类且无错误写入；数值核验预先指定独立来源和容差；现有性能门槛保留并披露失败样本。课堂规模与持续运行的新增性能目标在执行前写入验收配置，依据明确资源配置和首轮基线设定，不能测试后调整门槛使结果通过。

每个案例最终记录编号、代码提交、环境、数据 release、账号角色、前置状态、操作与故障点、预期、实际、数据库核对、截图/日志、两次复现结果和回归结果。测试结束产生覆盖矩阵、问题清单、性能分布、恢复演练记录与最终报告，并明确仍未覆盖的组合。
