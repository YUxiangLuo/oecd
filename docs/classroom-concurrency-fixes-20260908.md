最后一名等待者断开时，尚未开始的工作被撤销；运行中的数值工作在协作检查点退出。线程真正结束之前仍占用计算名额，避免取消请求后实际运行的线程突破上限。仍有其他学生等待时，共享工作继续。原始表切换、回归参数变化和离开步骤会中止失效请求。保存和提交继续使用现有事务、版本检查与重复提交语义。

运行期限不会强行杀死 Python 线程；无法中断的底层调用结束前会继续占用名额。上述期限从调度器接纳任务起算，认证、参数校验、前置数据准备和报告落库另计。普通保存和登录的 16 个线程不被排队中的 CPU 或原始表工作占用。

数据来自同一真实 OECD release `2de76298d79646509efe0dfb49d8065d`，Python 3.13.15、Uvicorn 0.49.0、12 个逻辑 CPU，1 个 API worker、16 个普通线程、4 个计算名额、8 个数据库连接、数值库 2 线程。测试经本机单 worker Nginx 和独立 PostgreSQL；没有覆盖校园网络、生产 TLS／HTTP/2。“冷”指应用缓存为空，未清空操作系统页缓存。同年原始表试验复用一个只读账号，跨年及其余课堂场景使用 50 个独立学生账号。

5 年完整表缓存实测 519.90 MiB；冷读后进程 RSS 970.80 MiB，重复查询后 979.66 MiB。这是本数据与测试路径的内存记录，部署仍需为其他缓存、报告与数值计算预留空间。50 个不同计算会触发受控拒绝，需要稍后重试；本次没有把单机变成可以无等待处理任意 50 个重计算的系统。

报告使用通过公共接口准备的完整课程夹具，四项规定回归均为可写入报告的 `invalid_design` 诊断；报告时延不代表所有可推断设计。不同置换使用合法 API seed 构造不同任务，界面默认固定 seed。共享计算的冷启动结果单独重启 API 测量，避免把已有缓存命中误记为任务合并。

自动化验证：后端完整 653 项通过，覆盖率 89.95%；前端完整 372 项通过；Ruff 格式与 lint、Mypy、TypeScript、生产构建及生产／演示构建边界全部通过。新增竞争时序测试使用真实线程、容量屏障和取消，覆盖超量准入、排队过期、取消后线程名额保持、缓存替换竞争、跨年份读锁和账号限额隔离。
